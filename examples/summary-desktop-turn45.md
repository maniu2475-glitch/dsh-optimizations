## Key Technical Concepts
- [fact] DSH 0.2.1-rc.3. Compaction = 4-plugin stack: token-meter → compaction-tool-result-pruner → compaction-basic (engine; provides `ctx.compaction`) → command-compact (`/compact`). Threshold math: `threshold = floor(min(contextWindow×thresholdRatio, messageBudget−headroom))`; desktop defaults → threshold 196608, retain 41943 (contextWindow 262144, headroom 65536).
- [fact] Compaction event protocol in `session.v4.jsonl.zstd` (concatenated zstd frames, magic 28 B5 2F FD): `compaction/start` → `compaction/summary` → user message (source.kind=compact-checkpoint, surfaceOp replace startSeq/endSeq) → `compaction/end` (error field present = failed; original events preserved).
- [fact] Stock `COMPACTION_INSTRUCTION` (8 sections) is a module-internal const in `app.asar` → cannot be configured or edited; only sanctioned hook = override `summarize()`. Stock flow: replay prefix + append instruction as final user message (warm prefix cache), `BlockAssembler` assembles chunks, `finishError` maps terminal finish (error/aborted/max-tokens) to thrown errors, `frameSummary()` wraps with CHECKPOINT_PREAMBLE + `<compacted-summary>` tags.
- [fact] `llm.stream()` chunk shapes (verified from dsh-llm source): `text-delta` carries `chunk.text`; `finish` carries `chunk.reason` = terminal `{kind, failure?}` (kind: stop|max-tokens|error|aborted); `usage` carries `chunk.usage`; `tool/result` events carry id at `data.toolCallId`.
- [fact] Cordis isolate semantics (measured, not guessed): a `cordis:group` row with `isolate: {compaction: true}` puts the group's services in a local realm; a plugin mounted OUTSIDE that group cannot see `ctx.compaction` — `ctx.inject(['compaction','llm'])` never fires. Plugin must be mounted INSIDE the same group's config.
- [fact] Cordis patch dialect rules (measured): a patch with different `name` for an existing id is rejected ("name mismatch", skipped); to swap, set `disabled: true` on the original row then `insert` a new id. An `insert:` list appends top-level rows; a lone `- id: compaction` inside insert does NOT merge into an existing same-id group — it creates a NEW group (verified via dump-config showing two groups).
- [fact] Custom plugins CANNOT import `@deepseek-ai/*` (packages live inside app.asar; profile-resolved import → ERR_MODULE_NOT_FOUND; `link:`/`file:` install both fail because pnpm linked deps don't resolve peer deps from target node_modules; installing `dsh-llm` into the profile → duplicate provider boot crash `configurable provider "amazon-bedrock" is already declared`). Working pattern: zero-Harness-import plugin + `ctx.inject` + wrap live service instance.
- [fact] Codex public design (raw.githubusercontent.com, fetched): `SUMMARIZATION_PROMPT` (4 fields: progress+decisions / context+constraints+preferences / remaining work / critical data), `SUMMARY_PREFIX` says "avoid duplicating work", `COMPACT_USER_MESSAGE_MAX_TOKENS = 20_000` (real user messages re-injected post-compaction, newest-first, over-budget message truncated), `normalize_history` enforces call↔output pairing invariants, ~4 bytes/token estimates, observability event with trigger reason/tokens before+after/duration. Claude Code docs pages were JS-rendered shells — unusable; Aider history.py facts from subagent (tail-keeping until ~half budget, split point backs up to assistant boundary, summary budget 1024, recursive depth 3).
